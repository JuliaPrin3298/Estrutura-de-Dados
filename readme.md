Padrão de Commits

Para manter o histórico do projeto organizado e fácil de entender, os commits seguem um padrão de abreviações. Cada abreviação indica o tipo de alteração feita, permitindo identificar rapidamente o propósito de cada commit.

Os principais tipos utilizados são:

EST – Alterações de estilização, como ajustes de layout, cores, fontes e espaçamentos. Exemplo: EST: ajusta espaçamento do cabeçalho

ATU – Atualizações de conteúdo, textos, imagens ou pequenas melhorias visuais. Exemplo: ATU: adiciona nova seção na página inicial

BUG – Correções de erros ou falhas no funcionamento do sistema. Exemplo: BUG: corrige erro no botão de login

NEW – Implementação de novas funcionalidades ou componentes. Exemplo: NEW: adiciona sistema de cadastro de usuários

REF – Refatorações no código, como reorganização de funções, limpeza de trechos redundantes ou melhorias de performance. Exemplo: REF: melhora a estrutura do código

TST – Criação ou atualização de testes automatizados. Exemplo: TST: adiciona testes para o componente de login

DOC – Alterações na documentação, como o README ou guias de instalação. Exemplo: DOC: atualiza instruções de uso

DEP – Atualizações de dependências, bibliotecas ou pacotes externos. Exemplo: DEP: atualiza dependências do projeto

DEL – Remoção de arquivos, códigos ou recursos obsoletos. Exemplo: DEL: remove imagens não utilizadas

DB – Mudanças relacionadas a banco de dados, conexões ou APIs. Exemplo: DB: ajusta estrutura de tabelas
